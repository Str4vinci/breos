# Manuscript v2 reproduction audit

This audit maps the results claimed in `BREOS_manuscript_v2.docx` to source
data that BREOS 0.6 must emit. Plot styling is out of scope. The requirement is
that each plot and table can be rebuilt from versioned configuration and
machine-readable outputs with recorded provenance.

## Methodology discrepancies to resolve

1. The manuscript says the annual load multiplier is uniform on 0.95-1.05.
   The archived July implementation sampled a normal distribution with mean 1
   and standard deviation 0.05. The new Article configuration follows the
   stated uniform method. The manuscript and configuration must remain
   consistent after the new run.
2. The archived nominal 15-minute optimization repeated hourly irradiance
   values. BREOS 0.6 uses clear-sky interpolation with opt-in hourly-energy
   conservation and a finite inverter. The old Pareto and representative
   values must not be retained as if they came from this corrected workflow.
3. Monte Carlo headline grid independence should use lifetime import divided
   by lifetime load. The mean of annual percentages remains available as a
   diagnostic but is not the lifetime definition used by projected
   optimization.
4. The manuscript reports fractional break-even years. Use
   `payback_year_exact`, which linearly interpolates the discounted cumulative
   cash-flow crossing, rather than the first positive integer year.

## Release gate

Before tagging 0.6.0:

- merge projected optimization and detailed fixed-design exports;
- merge reproducible Monte Carlo distributions, yearly trajectories, worker
  control, and provenance;
- decide whether orientation, weather comparison, load sensitivity, and
  projected emissions are part of 0.6.0 or a separate Article data package;
- run the final deterministic v1, field-v2, and laboratory configurations;
- run the final Monte Carlo configurations;
- update every affected manuscript number from those final outputs;
- add Code Availability and Data Availability statements that cite the 0.6.0
  archive/DOI, identify the licensed E-REDES input, and identify any
  third-party validation data;
- archive the generated CSV/JSON source bundle outside Git if its size is not
  suitable for the repository.

Generated scientific results belong under the ignored `results/` directory.
The version-controlled configs, orchestration commands, regression tests, and
reproduction report templates belong in the repository.
